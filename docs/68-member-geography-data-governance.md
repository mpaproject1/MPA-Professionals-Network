# Member Geography Baseline, Governance and Workbook Operations

## Baseline reference package

The starter workbook is generated by \`scripts/generate-member-geography-reference.js\` and validated by \`scripts/validate-member-geography-reference.js\`.

It contains:

- UN Statistics Division M49 country/area entries with ISO alpha-3 and three-digit M49 identifiers. M49 is a statistical reference and does not itself determine sovereignty or legal status.
- Ethiopia (ETH), M49 231.
- Ethiopia's 12 regional states and two chartered cities, retaining the existing stable MPA internal identifiers for those level-one units.
- The pinned Ethiopia administrative dataset's zones, sub-cities/city divisions and woredas, with original source IDs, bilingual/local labels where supplied, coordinates and row-level provenance.
- The existing country-level-only treatment for non-Ethiopian countries. Foreign provinces, states and cities are not inferred.

## Ethiopian source mapping and exclusions

The workbook uses the source repository at [Jafermenza/ethiopia-administrative-divisions](https://github.com/Jafermenza/ethiopia-administrative-divisions), pinned to commit \`418739e33760bf79661f3914e2d8c9cf33248437\` (release date 8 September 2026; CC BY 4.0). The source describes its Ethiopia data as derived from OCHA COD-AB / HDX. The source is pinned so a later upstream edit cannot silently change the generated workbook.

The reviewed mapping for this source release is:

| MPA level | Records | Mapping |
|---|---:|---|
| Region | 12 | Existing MPA regional-state codes retained |
| Federal City | 2 | Addis Ababa and Dire Dawa |
| Zone | 101 | Source zones under the 12 regional states |
| Sub-city / City Division | 13 | 11 Addis Ababa sub-cities and Dire Dawa urban/rural divisions |
| Woreda | 1,119 | Woredas under regional zones and Dire Dawa city divisions |

Two source-specific hierarchy decisions are important:

- Addis Ababa's source contains one synthetic grouping named **Region 14**, with 11 children explicitly named as sub-cities. The synthetic grouping is not imported as a zone; the 11 named sub-cities are placed directly beneath the Addis Ababa federal-city record.
- Dire Dawa's two source zones are named **Dire Dawa urban** and **Dire Dawa rural**. They are represented as city divisions beneath the Dire Dawa federal-city record, and their 13 woredas remain beneath those divisions.

The source also contains a **Contested** grouping with three zones and 18 woredas. That grouping and all descendants are deliberately excluded from the selectable hierarchy. They must not be silently represented as an ordinary region. A future policy decision may add a separately governed disputed-area model if required.

The source does not define an independent sub-city layer for all cities. No missing sub-cities or other units are invented. Addis sub-cities are only included where the source explicitly identifies them.

Primary sources:

- UN Statistics Division M49: https://unstats.un.org/unsd/methodology/m49/overview/
- Ethiopia administrative divisions dataset (CC BY 4.0): https://github.com/Jafermenza/ethiopia-administrative-divisions
- Pinned source commit: https://github.com/Jafermenza/ethiopia-administrative-divisions/tree/418739e33760bf79661f3914e2d8c9cf33248437
- Underlying OCHA COD-AB / HDX source referenced by the dataset: https://data.humdata.org/dataset/cod-ab-eth

## Hierarchy and validation contract

- Country: no parent; requires ISO alpha-3 and UN M49 codes.
- Region or Federal City: parent must be Ethiopia (ETH).
- Zone: parent must be a Region.
- Sub-city / City Division: parent must be a Federal City.
- Woreda, District or Town: parent must be a Zone or Sub-city / City Division.
- Every imported row has a stable unique unit code, label, source name, source version, HTTPS row-level \`metadata.sourceUrl\`, and valid effective dates.
- Ethiopian source identifiers are retained as stable unit codes for lower levels; the existing MPA internal codes remain in use for regions and chartered cities.
- Parent references must resolve within the same workbook/version. Country ISO/M49 uniqueness is enforced by database indexes.
- Only active countries marked residence-selectable appear in member country selection.
- The residence selector exposes up to three Ethiopian administrative choices after the country: Region/Federal City, Zone/City Division, and Woreda/District/Town.

## First-time initial publication

1. Run the **Member geography reference workbook** workflow on the target branch.
2. Download the generated \`member-geography-reference\` artifact, including the XLSX workbook and manifest.
3. In Admin → Membership Center → Member geography, upload the workbook. Use the combined UN M49 / Ethiopia source name, the generated source version and the repository URL as the primary source URL.
4. Preview and resolve every validation error. Applying creates a draft version only.
5. Review the source and hierarchy, enter the audit reason, and publish. Publishing switches member selectors to the new version; it does not mutate earlier versions.

The repository workflow creates and validates the starter workbook. It does not connect to or silently seed a production database. Initial publication is an explicit administrator action in the target environment.

## Export, amend and re-import

1. Use **Export published geography** to download the exact currently published version as XLSX.
2. Amend labels, activity, source provenance or hierarchy while preserving stable \`unit_code\` values and the complete required column set.
3. Do not convert Woreda rows into District rows merely for convenience; keep the administrative level explicit. Add or change source records only with documented provenance.
4. Upload the amended workbook and preview it. An import creates a new draft version; it never edits a published version in place.
5. Apply and publish only after the preview is clean and the audit reasons are recorded.

Do not remove a country or unit that is referenced by historical member residences without considering those retained version references. Published versions are immutable historical snapshots.
